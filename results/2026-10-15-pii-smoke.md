# Synthetic PII scenario smoke test — 2026-10-15

One paired run per scenario and model used OpenCode 1.19.0, GPT-4.1 mini and
Claude Haiku 4.5 through OpenRouter, and Pentect 0.0.95. Pentect's isolated
test configuration set `protection.pii = true`. All contacts, places, and records were fictional;
the only card number was a public test card. No real email or payment was sent.

| Model | Task success without / with Pentect | Exact watched fixture values sent to model without / with Pentect | Runs with any watched value without / with Pentect |
| --- | ---: | ---: | ---: |
| GPT-4.1 mini | 6/6 / 6/6 | 26/30 / 12/30 | 6/6 / 6/6 |
| Claude Haiku 4.5 | 6/6 / 6/6 | 22/30 / 12/30 | 5/6 / 6/6 |
| **Total** | **12/12 / 12/12** | **48/60 (80%) / 24/60 (40%)** | **11/12 / 12/12** |

In the plain-text cases, the standard detector hid the synthetic email and
phone but did not hide the fictional name and address. In the obfuscated case,
the full-width phone was hidden; the `[at]` email, name, and address were not.
The encoded payload itself reached the model in both arms. In one direct CSV
run, the model counted locally without sending any watched field to the
provider; the Pentect run used a different tool path and did send two fields.
These are observations of exact watched strings, not a comprehensive
PII-leak detector.
Every protected scenario had at least one watched value reach the model.

This was a smoke test with one trial per model and scenario. It verifies the
fixtures and scoring path, not a stable protection rate or a security guarantee.
No pair was discarded or left incomplete.
